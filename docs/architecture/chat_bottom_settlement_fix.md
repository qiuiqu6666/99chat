# 手动回底与回弹来消息：修复记录

本次修复针对 2026-09-22 的两个反馈：手动读完新消息后仍出现“回到底部”；轻微回弹后收到新消息，列表尚有内容在下方却没有提示。修复接入现有生产列表，统一运行时的整体迁移仍未完成。

## 原因与改动

- 胶囊构建和滚动结算各算一次“真实最新端”，其中一处遗漏待入窗消息。现在使用同一个判断，包含内存待入窗、持久待确认和历史缺页。
- 原策略即使有未见消息，也要求离底部半屏才显示。现在尚未到真实最新端且有未见消息时优先显示计数。无新消息的普通回底按钮仍保留距离与滞回规则。
- 恢复跟随只迁移消息 ID，却留下旧 receivedCount。现在完整覆盖、收件代次和待处理数据检查通过后同步收敛，保留访问代次与去重身份；部分覆盖拒绝恢复跟随。
- 可见性采样检查消息行身份与布局有效性。普通消息完整进入视口、超高消息底边进入视口才消费胶囊计数，避免预加载行或边缘露头提前清除提示。
- 有效可见行可以在阅读历史时推进持久已读，无需先恢复跟随。持久 receivedCount 根据实际剩余回执发布，允许下降；胶囊 remainingLiveIncomingIds 独立维护，SQL ACK 本身不清除它。
- 几何到底但持久确认尚未完成时，不再提前跳过确认分支。结算未成功时，两个直接结算入口不会自行清除胶囊状态。
