# 阅读历史时持续接收新消息

分支：`codex/chat-live-history`，基于 `278e121`。

## 实现行为

- 连续连接最新端的窗口：走正常 Writer 的插入、排序和去重流程；用户看历史时追加消息，但不请求贴底、不清未读。
- 存在历史缺口、搜索定位、待补入消息或受保护覆盖层：保持现有持久分页流程，禁止跨越缺口拼接。
- 真正位于最新底部：保留现有自动跟随和入场展示。

阅读窗口绑定增加连续性判断和已插入回调。正式插入后推进页面模型的最新边界，避免新消息被旧的冻结边界过滤。没有提供新回调的兼容调用仍保留保守行为。

列表在布局前按旧消息身份捕获阅读位置，以固定的 sliver 起点承接新消息。拖动中也可保持阅读内容。布局测量持有实际 RenderObject，避免从索引映射访问已经失效的组件。

插入不等于已读。计数按消息身份去重，可见性验证检查实际行身份，并排除隐藏的裁剪、搜索过渡布局。回底确认要求最新气泡已经呈现；只结算已确认或先前已看见的本地身份，保留后续持久接收批次。

连续窗口将合批中的消息纳入 3000 行预算；阅读期间的常规空闲裁剪和分页高水位也按这个预算处理，并为一页历史消息留出空间。容量满时先提交已预留的前缀，再标记缺少更新记录，后续消息进入持久分页。裁剪继续保留阅读锚点。没有修改数据库结构或持久格式。

## 验证

- 历史向下分页和窗口集成中的 13 个失败用例已修复：可见行确认推进未读计数、真正抵达最新端后结算剩余计数、分页布局恢复后刷新胶囊几何。连续连接的实时消息测试按直接追加语义校验阅读锚点；胶囊接近底部时仍遵守半屏显示阈值。
