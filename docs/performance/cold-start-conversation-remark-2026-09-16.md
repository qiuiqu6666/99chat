# 冷启动会话备注被昵称覆盖

## 已确认的客户端原因

冷启动 HomeBootstrap 先恢复会话投影，再异步预热可见会话的好友备注。
头像、SDK 用户资料等加载可同时访问 UserProfileLocalService。会话行的
FriendDisplayName.resolveC2C 优先读取该服务内存中的备注，其次是昵称。

原实现有三处不一致：

1. read 在等待用户资料库期间，好友库可能已把正确备注预热到内存。
   旧读取完成后仍返回旧值，并可覆盖内存；即使旧读取返回 null，后续
   saveUserFullInfo 也会据此构造无备注资料并发布昵称。
2. hydrateFromFriendRecords 跳过所有已缓存用户，无法区分“只有公开资料”
   与“已确认备注为空”。公开资料先返回时，真正的好友备注无法补入。
3. 预热拒绝旧快照后，seedC2cDisplayNamesFromFriendRecords 仍直接使用旧
   快照更新 DisplayNameStore 和会话投影，与内存真源不一致。

## 修复

- 异步本地读取返回前复查内存，保留期间已完成的预热或修改。
- SDK/公开资料写入保留当前备注；落盘期间若缓存变化，则合并最新备注
  后重新落盘，再发布，避免只修 UI 而留下错误数据库记录。
- 以弱引用记录备注是否来自好友资料或显式修改；公开资料的空备注允许
  被预热补齐，主动清空的备注受到保护。跟随资料对象回收，不增加无界 ID 缓存。
- 备注预热、DisplayNameStore 和会话投影采用同一份合并结果。
- 无新增网络请求，也不扩大启动时现有最多 100 个可见 C2C 用户的预热范围。

## 验证

新增 test/cold_start_remark_race_test.dart，覆盖：

- 读取期间预热备注，旧读取不能覆盖新内存。
- SDK 资料保存完成后仍显示备注。
- 公开资料先入缓存、好友备注后预热。
- 主动清空备注后预热和刷新不能恢复旧备注。
- 公开资料保存期间预热，数据库与重新读取结果均保留备注。
- 旧好友快照不能把已确认清空的备注重新写入显示缓存。

修改前，前三项对应的时序测试失败，其中 SDK 保存用例由“好友备注”
变成“更新昵称”。修改后新增用例及 6 个相关测试文件共 42 项通过。
涉及的两个生产文件及新测试文件 Dart 静态分析无问题。

GitNexus 使用仓库 99999999、2026-09-16 的索引完成修改前影响检查。
资料 read/_saveAndPublish 为 MEDIUM，名称批量发布为 LOW；部分动态调用
无法由索引解析，另以源码核对头像、聊天标题、资料页及好友同步调用。

这是客户端源码及 Flutter/SQLite FFI 回归验证；尚未进行 Android 真机
冷启动录屏或抓取该账号的服务器响应，不将测试结果当作真机复测结果。
