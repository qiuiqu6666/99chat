# 万人规模客户端优化：首轮落地记录

日期：2026-09-25。基于此前规模审计，修改当前 Flutter 工作区；尚未发布安装包。

## 已落地的行为

| 区域 | 实施内容 | 验证结果 |
| --- | --- | --- |
| 冷启动恢复 | `SessionManager.restore()` 的界面等待限制为 8 秒；有本地身份时进入离线状态。底层鉴权、SDK 登录仍保留同一个进行中的任务，迟到的鉴权失效仍退出，迟到的成功仍恢复连接。 | 模拟鉴权或 SDK 一直等待，9 秒时界面等待已结束；重复恢复和重连不会额外启动第二次登录；迟到 401 与成功均覆盖。 |
| 在线状态 | 失败后指数退避并加入随机延迟，尊重 `Retry-After`；紧急刷新共用同一个截止时间；成功、会话清理时重置。非重试型 HTTP 错误不自动重新入队。 | 相同快速 503 场景，2.6 秒窗口从审计时的 6 次请求降至 2 次；本轮间隔 1,131 毫秒。 |
| 代理下级 | 首屏只拉 50 条；显式加载下一页，避免自动拉完一万条。资料查询由可见行触发，整页共用 4 个实际运行槽位，刷新和销毁有代次隔离。 | 一万条数据、不滚动时：51 次分页 → 1 次；408 个同时未结束的资料请求 → 4 个。额外翻页时旧请求不结束，仍保持 4 个槽位。 |
| AI 助手 | 历史列表改为按需构建并按索引定位搜索结果；图片只预取可见附近范围；下载去重、页面并发 2、等待队列 32、原始字节缓存预算 24 MiB。历史消息对象不重复持有下载字节；普通附件在点击时下载。 | 一万条文本历史只构建有限行；搜索能够定位到原本未构建的旧消息。下载队列、去重、字节淘汰、销毁后迟到结果有测试。 |
| 朋友圈评论 | 评论从整列构建改为列表按需构建，直接按下标取评论，移除逐条 `indexOf` 的平方级重复查找。 | 一万条评论首屏只构建可见附近行；滚动到后续区域仍保持有限构建量。原评论删除权限测试通过。 |
| 手机通讯录 | 每 500 个本地联系人完成一批匹配就发布结果；离开页面、重复加载、账号变化时停止后续批次及过期结果提交。 | 一万联系人在首批 500 条后即可收到结果；首批后取消不会继续发第二批请求。 |
| 直播成员选择 | 每次加载最多两页，每页 100 人，保留真实游标；支持继续加载和失败重试；未加载完整时明确搜索范围。 | 一万成员场景首轮仅两页、200 人；下次从后续游标继续。现有选择器行为通过。 |
| 管理用户列表 | 按需构建列表；同一搜索词最多自动补一页，其余显式继续加载。 | 通过编译与针对改动文件的静态分析；尚未新增该页面的独立大数据界面测试。 |
| 钱包流水 | 按账号、筛选条件、页大小保存续页位置；首批 ID 指纹变化则重新校验，避免每次都从相同历史页重拉。每页写入后让出执行时间；有缓存时，历史页刷新等待最多 2 秒，随后复用原请求完成更新。 | 实际接口入口测试得到页序列 `0,1,2` → 下次 `0,3,4`；首批变化后恢复 `0,1,2`。慢刷新先返回旧记录，迟到的新记录写入缓存，没有第三次重复请求。 |

## 代码入口

- `lib/src/session/session_manager.dart`：启动等待与重复恢复保护。
- `lib/src/provider/presence_provider.dart`、`lib/src/services/request_retry_backoff.dart`：在线状态失败退避。
- `lib/src/pages/agent_rebate_descendants_page.dart`：按需分页与资料查询队列。
- `lib/src/pages/ai_assistant/ai_assistant_page.dart`、`lib/src/services/bounded_file_loader.dart`：按需渲染与附件资源预算。
- `lib/src/pages/moments/moments_detail_page.dart`：评论懒构建。
- `lib/src/services/contact_friends_lookup_service.dart`、`lib/src/pages/contact_friends_page.dart`：渐进匹配及过期结果保护。
- `lib/src/pages/group_live/group_live_member_loader.dart`、`group_live_member_picker_page.dart`：成员加载预算与继续入口。
- `lib/src/pages/group_game/sangong_all_users_page.dart`：管理列表分页与按需渲染。
- `lib/src/api/wallet_api.dart`、`lib/src/services/ledger_page_progress.dart`、`wallet_ledger_local_store.dart`：流水续页、缓存等待预算和账号隔离。
- `pubspec.yaml` / `pubspec.lock`：将已有的 `intl` 和仓库内 `scrollable_positioned_list_for_us` 声明为直接依赖，未升级依赖版本。

## 尚未验证或需要后续接口配合

1. 没有执行一万真实客户端同时上线的服务端压测，也没有完成低端 Android / iPhone 的真机帧耗时、内存峰值和断网重连测试。本轮数值来自确定性的模拟与组件测试，不能据此宣布已达到万人容量。
2. 代理、管理列表和直播成员选择的搜索范围目前是已加载数据。完整的一万条全局搜索、全局排序需要服务端查询支持；界面已提示当前范围。
3. 朋友圈接口仍返回整份评论，本轮降低的是构建和重复遍历成本；完整解决网络响应、JSON 解析、模型内存，需要评论游标分页接口。
4. 钱包目前仍使用页码协议。首批指纹能发现常见新增造成的位置漂移，但无法证明同步期间所有插入、删除都不会造成偏移。稳定的历史覆盖仍需要后端提供快照/游标，且后台新数据不会自动让已经显示的流水页面重建，需页面再次读取或刷新。
5. AI 的 24 MiB 限制只针对下载的原始字节缓存；文本历史模型、显式打开的大文件以及 Flutter 解码图片缓存属于其他内存来源，尚未实现历史模型滚动淘汰或落盘附件缓存。历史名片补全仍按现有逻辑执行。
6. 8 秒限制释放的是启动界面等待，没有伪装成取消底层 SDK 登录。若 SDK 永远不回调，原任务仍占用运行槽位；完整的连接恢复还需要 SDK 连接状态与取消/重建策略配合。
7. 本轮降低了请求放大和单页工作量；集中上线仍需服务端限流、批量查询、缓存与容量压测共同验收。

保留工作区其他任务的现有改动；没有创建提交、推送或发布。
