## 已确认的问题与修复

截图表现为消息通知已到、未读徽标已变，但旧预览/旧位置仍被保留。未读数、消息预览、列表排序由不同更新入口处理，某一个入口成功不能证明整行已同步。下面的问题已由源码与自动化用例确认；未取得截图发生时的手机日志，因此不把某一条分支认定为该次现场的唯一原因。

1. **消息先于会话资料到达时被丢弃。** `applyLastMessageLocally` 找不到行就返回。新增最多 512 个会话的暂存预览，在 SDK 会话回调、分页和窗口恢复时合并最新消息；保留 SDK 未读数，不自行重复累加。账号清理、删除、显式清空均会失效暂存数据。延迟窗口请求还检查会话生命周期代次。
2. **SDK 原地修改消息对象，被当作无变化。** 原先根据对象引用相同提前返回。现在交给 Store 保存的字段快照判断，真正变化时发布行内容及排序更新，重复消息仍能去重。
3. **旧草稿时间压住新消息排序。** 排序活动时间改为草稿时间与最后消息时间的较新值，并统一秒/毫秒。持久化计算使用相同规则；置顶优先级保留。
4. **滚动暂停排序的状态残留。** 跟踪实际 ScrollPosition 的通知对象，在隐藏、控制器/位置更换和销毁时解绑；每个列表只释放自己的暂停状态，最后一个使用者退出后提交待排序变化。重复滚动状态不会逐帧强制刷新 SDK 批次。

另修正验收期间出现的联系人同步编译阻碍：`contact_sync_transaction.dart` 中将响应变量明确为 `SyncStatusResponse`，避免可空初始参数影响重试结果的类型推导。仅补充类型，未修改联系人同步业务分支。
