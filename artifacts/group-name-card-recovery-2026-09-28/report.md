# 群昵称保存失败排查与修复

日期：2026-09-28。工作区基线：0e7aa83bc5b096a99ff8bb424842404a3c901cb7。

截图只能确认用户看到“保存失败”，没有服务器错误码，不能据此判定本次实际失败原因。按图中可见内容 `京东🌇公平公正/16.35元红包金额` 计算为 43 个 UTF-8 字节，未超过腾讯群名片 50 字节上限；中文、表情或金额文字本身不能作为失败结论。官方约束：[修改群成员资料](https://cloud.tencent.com/document/product/269/1623)。

## 已确认的代码缺陷

1. `TUIGroupProfileModel.setNameCard` 先读取 SDK 完整用户资料；资料为空直接返回 null。即使业务登录有效、自建 REST 接口可用，也不会发出保存请求。
2. 群资料页先显示具体失败原因，通用昵称编辑页收到 false 后再次显示“保存失败”，覆盖前一个提示。REST 服务还把 DioError 转成字符串，丢失结构化业务错误。
3. 服务端提交与本地数据库更新混在同一个 try/catch。后者异常会将已提交的修改误报为失败。模型还在写入成功后等待另一次成员查询，延长等待并增加失败机会。
4. 保存缺少明确超时和异步结果归属检查。旧入口的保存锁没有 finally，异常后可能持续阻止提交。
5. 输入框按可见字符限制，策略按 UTF-16 长度检查，且未检查 UTF-8 字节限制；部分表情被错误拒绝，部分超长中文昵称被错误放行。

## 修复内容

- 自建接口以业务登录账号为准；SDK 路径核对账号，拒绝旧账号状态下的请求。
- 将可读错误作为独立异常传给编辑页，在输入框下保留提示；失败后仍可再次提交。
- REST 等待上限 12 秒，超时取消传输；提示“保存结果暂未确认”，不假定远端已回滚。保存操作本身有 18 秒上限。
- 已确认的服务端保存与本地投影分开处理；本地更新最多等待 2 秒，其失败不改变保存结果。模型直接更新昵称字段，不再依赖额外的成员查询。
- 账号代次、群、页面生命周期和操作版本共同校验，丢弃迟到结果；所有临时请求记录和旧入口的锁在 finally 清理。
- 统一可见字符计数并增加 50 字节检查；不静默截断昵称。
- 记录点击、REST/SDK 分支、请求、返回码、服务端确认、本地更新、失效结果和界面通知。日志记录长度，不记录昵称正文或凭据。

- 没有操作真实账号或线上昵称；没有提交、推送、部署或制作新安装包。仍需 iOS/Android 真机弱网与实际后端联调。

## 影响分析与限制

修改前使用 GitNexus：保存方法有两个直接入口，风险 HIGH；模型类涉及 29 个直接调用方，风险 HIGH；共用群同步服务类风险 CRITICAL。改动限定于群昵称路径及其错误处理，未改变群权限、入群/退群和其他资料编辑规则。两个 updateMyNameCard 方法图查询为 UNKNOWN，已用源码确认桥接回调与服务调用关系，没有把空调用图作为安全结论。

当前后台源码会将腾讯 REST 异常归并为 IM_REST_ERROR。本轮客户端能保留业务错误码及请求阶段，但不能从截图还原腾讯侧当时的具体拒绝原因；需要对应的服务器日志。HTTP 超时后的远端结果也可能已提交，客户端不会自动重复发起写入。

原工作区其他稳定性修复保持原状。此记录只覆盖群昵称问题，不表示整个 App 已通过发布验收。
