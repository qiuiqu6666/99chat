# 群昵称页面个人资料缺失补充修复

日期：2026-09-28。延续同目录 report.md 的群昵称保存修复。

## 确认的问题

群昵称编辑入口只在打开时读取一次 SDK 个人资料。资料晚到后没有订阅刷新；完整 SDK 用户资料为空时，也无法根据业务登录账号正确匹配自己的群成员昵称。此前保存路径还把 SDK 完整资料当作前置条件，该保存缺陷已在上一轮修复。本轮补齐显示与页面生命周期链路，不把头像或昵称加载成功作为保存条件。

## 本轮改动

- 新增页面独享的 GroupNameCardProfileSource：按当前账号读取内存资料、账号隔离的本地资料、匹配账号的 SDK 资料和群成员资料；资料缺失时并行读取本地与 /me。
- 订阅个人资料、群资料及成员数据变化，刷新已打开页面。自动填充仅限未修改且未处于输入法组合状态的输入框；用户草稿保持不变。
- 资料读取有 6 秒超时和独立取消对象；失败后显示单独的重试入口，仍允许填写并保存群昵称。重试不取消其他页面的请求。
- 关闭编辑页移除监听并取消页面请求；账号代次或群发生变化后丢弃迟到结果，旧页面不能给新账号提交昵称。
- 自己的群名片回退查询使用业务会话账号，不再依赖 SDK 完整资料中的 userID。
- 资料补齐仅由群昵称入口启用。桌面共用弹窗的 builder 返回类型放宽为 Widget，以承载监听组件；其其他调用方和保存规则不变。
- 增加资料加载、就绪、本地不可用和远端不可用阶段日志，不记录资料正文或凭据。
