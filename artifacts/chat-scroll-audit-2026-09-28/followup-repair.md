# 点击新消息与连续下滑补充修复

2026-09-28。对应用户补充的两项问题：点击新消息后提示重试，以及一边向下滑一边收消息时反复追不到底部。代码已修改，未提交、打包或安装到手机。

## 原因与修改

1. **回底确认过早结束。** 真机日志记录了滚动距离已到 0，但最新行尚未呈现时立即结束回底。测试还复现了旧消息更新使已捕获的可见快照失效、已有历史请求尚未结束两种情况。现在会在当前回底操作内重新获取有限次数的真实帧和消息身份；已有历史请求不消耗这段短重试次数。保留 25 秒总超时、主动拖动取消、会话与账号隔离、SDK 失败处理，以及严格的可见性确认。
2. **手指未松开时，最新边缘继续增长。** 真实列表测试中，到达底部后每条较长消息可让视口再次落后 180px。现在仅在该手势已经抵达真实最新行后，在布局阶段补偿新消息引起的底部增长，不通过跳转或动画取消手势。测试逐帧验证退后不超过 4px，并验证最新行的实际矩形位于视口内。
3. **轻微反向仍被视作跟随。** 原来同一手势反向 12px 后，新消息可被当成已跟随，产生距离底部 76px、计数却为 0 的状态。现在已有真实底部控制权的手势一旦明确反向，立即交还历史阅读控制；新增不可见消息保留提醒。没有泛改其他场景的原有滚动阈值。
4. **完整已发布的待确认消息可以保持跟随。** 已发布到列表、仍等待持久化可见确认的完整尾部，不再被误判为缺口。真实历史缺口仍禁止贴底；滚动补偿本身不清除未读。

生产改动位于 UIKit 的列表文件及回底提示容器。工作区其余未提交改动来自此前工作或并行任务，未整体覆盖。
