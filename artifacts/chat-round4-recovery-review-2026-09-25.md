## 仍然阻断发布的正确性与安全边界

1. **媒体公开访问：高优先级。** `ChatAttachmentOssClient.setPublicRead` 仍调用 `CannedAccessControlList.PublicRead`。阿里云文档明确说明：在没有 Block Public Access 等上层拦截时，显式 public-read 对象允许匿名读取，且对象 ACL 优先于 Bucket ACL。仅将 ACL 失败改为可见失败，不能解决成功设为公开后的访问控制。需要私有对象的接收端访问契约和真实 OSS/CDN 测试。参考：[阿里云对象 ACL](https://www.alibabacloud.com/help/en/oss/user-guide/object-acl)、[Block Public Access](https://www.alibabacloud.com/help/en/oss/user-guide/block-public-access)。
2. **unknown 对账：高优先级。** 客户端仍保持 unknown 不自动重发；服务端原生视频也只查询本地状态，没有基于精确 IM 证据的定期收敛。无证据时必须维持待确认，不能从“查不到”推断未发送。
3. **已读 blocked 原因：中高优先级。** 新水位、重连、频控已分开；`blocked:sdk_*`、`blocked:storage_*` 仍缺少“凭据已应用 / 存储已健康 / 会话权限已刷新”这类已核验的恢复入口。不能靠前台事件统一清空 blocked，也不能重置已有预算。
4. **Web 可验证性：高优先级。** `flutter test --platform chrome` 和 `flutter build web` 在应用/三方 SDK 编译阶段失败，不能据 Dart 静态分析和内存测试宣称浏览器事务、多标签竞争通过。IndexedDB cursor 使用对象主键；未来若改为非唯一索引分页，续扫位置必须同时包含索引键与主键。参考：[W3C IndexedDB 规范](https://www.w3.org/TR/IndexedDB/)。
5. **超过 5000 项的孤儿清理：中优先级。** 目前保守跳过，避免部分引用集合导致误删。若要推进，必须实现候选分批、完整引用核验，并使新引用登记与删除资格互斥或受版本约束；单次“删除前再查”不足以防竞争。

## 数值解释与需要采集的数据

- 客户端 Prepared 的 `100 × 10` 是每轮检查预算，后续 100 ms 续扫；它不是总任务数上限。1 秒提交后检查、5 秒租约失败重试、1 分钟低频兜底是当前调度值，尚无实际尾延迟证据证明最优。
- 客户端已读每页 500、每轮 20 页，按会话键推进；15 分钟重试窗口与指数退避上限 64 秒继续生效。频控码的 12 秒为最低冷却，不应被普通 2 秒退避覆盖。
- 服务端原生视频锁期 60 秒；定时任务每次最多 8 条，完成后再等 15 秒。单执行者在忽略处理时间时恢复上限才约为 32 条/分钟；这不是整个消息系统吞吐。应记录最老可执行任务年龄、每轮成功/受阻数、执行耗时和锁过期后写回结果，之后再调这些值。
- 需要结构化记录扫描是否耗尽、游标、停止原因、下一次唤醒条件，以及 blocked 原因分布；现有日志只覆盖部分扫描事实，尚不足以决定并发或缓存参数。
