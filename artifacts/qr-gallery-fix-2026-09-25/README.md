# 相册二维码卡顿与选码修复

## 本次改动

- 文件读取、位图解码、缩放、灰度增强、原生 ZXing 调用和 Dart 兜底均进入独立 isolate。
- 同次任务复用解码后的位图；原生多轮识别不再每轮重新读取、解码文件，也不再通过临时 JPEG 做增强。
- UI 线程控制总超时和取消。返回页面、手动取消后，迟到的结果不会导航；正在执行的原生同步调用可能要执行完才能退出，不能视为已被立即中断。
- 打开相册前暂停相机，选图、识别和选择结果期间抑制相机恢复和检测回调；退出相册流程后仅在应用前台恢复。
- 兼容当前 URL 与旧 JSON 业务码，按目标类型及 ID 去重。存在唯一业务目标时优先选取；多个业务目标或多个普通码时由用户选择，取消不跳转。钱包模式保留原有地址筛选和确认。
- 增加 32 MiB 文件与 4096×4096 像素上限作为平台预处理失败时的防护。超时、大图、损坏图片有区分提示。
- 保留原引擎顺序：移动端原生 ZXing，Dart ZXing 兜底。尚未根据失败原图确定最终主引擎。

## 可重复的修复前后对比

环境：Windows、Flutter 单元测试 Debug，纯 Dart 兜底路径。两张仓库现有图片，每张连续三次；相同脚本在修复前后运行。不是 Android/iOS 真机数据，也不是用户这次实际失败图片。

| 样本 | 指标 | 修复前（三次） | 修复后（三次） |
| --- | --- | --- | --- |
| 保存的二维码卡片（803×1024） | 总耗时 ms | 172 / 98 / 72 | 183 / 101 / 75 |
| 同上 | UI 事件循环最长间隔 ms | 169 / 98 / 72 | 11 / 12 / 11 |
| 同上 | 采样进程 RSS 增量 MiB | 8.55 / 16.93 / 20.88 | 45.34 / 11.85 / 13.14 |
| 整页截图（470×1024） | 总耗时 ms | 43 / 40 / 44 | 45 / 41 / 42 |
| 同上 | UI 事件循环最长间隔 ms | 43 / 41 / 43 | 11 / 11 / 11 |
| 同上 | 采样进程 RSS 增量 MiB | 4.80 / 8.43 / 6.20 | 10.82 / 9.36 / 4.24 |

两张图修复前后每次均返回正确目标。另用已入库的基准测试核对目标 ID，6/6 次正确，P50 44 ms、P95 178 ms。

结论：这组样本支持“CPU 识别不再阻塞 UI”；不支持“识别算法更快”或“内存更少”。创建 isolate 带来首次开销。RSS 是每 10 ms 采样的整个进程增量，受 GC、JIT 和运行时分配影响，并非精确单任务峰值；旧版阻塞 UI 也会阻塞采样，因此不能将两个增量直接当成内存优劣结论。

## 验证

30 项测试通过：已有卡片/截图解码、URL/JSON 兼容、多目标与去重、登录码、钱包候选保留、坏图/大图、取消/超时后再识别，以及选择弹窗取消/选中/长列表。

定向静态分析无 error/warning；扫描页面保留两个既有 info（构造参数建议、群资料加载后的 BuildContext 提示）。

GitNexus 已执行编辑前影响分析并结合源码核实；索引部分 Dart 调用关系返回 UNKNOWN、CRITICAL 或截断，不能作为完整影响范围证明。

当前只连接 Android 模拟器，未做实际手机上的相册生命周期、原生 FFI 识别和内存复测。现有原生 FFI 的内存释放行为也需在引擎比较时单独核验。

## 后续失败原图对比

桌面基准（默认不参与普通测试）：

```powershell
flutter test --no-pub --dart-define=QR_GALLERY_BENCHMARK=true test/qr_gallery_benchmark_test.dart --reporter expanded
```

实际图片在本机保留原文件，另建 JSON 清单；路径相对清单目录。业务码可写 expectedIds，普通码可写 expectedValues。基准只记录样本序号、正确与否和指标，不输出文件名、ID 或二维码内容。

```json
[
  {"file": "failed-image.png", "expectedIds": ["目标用户或群ID"]},
  {"file": "two-codes.png", "expectedValues": ["第一个原始内容", "第二个原始内容"]}
]
```

```powershell
flutter test --no-pub --dart-define=QR_GALLERY_BENCHMARK=true --dart-define=QR_GALLERY_BENCHMARK_MANIFEST=C:/qr-samples/manifest.json test/qr_gallery_benchmark_test.dart --reporter expanded
```

真机运行可加 `--dart-define=QR_GALLERY_PROFILE=true`，从 `[QrGallery]` 日志采集引擎、轮数、耗时、状态和采样 RSS 增量，不记录敏感载荷。

收到失败原图及机型后，在同一手机、同一构建模式下，对原生 ZXing、Dart 兜底和拟评估的新引擎分别测冷/热耗时、P50/P95、正确目标覆盖率、误选情况和系统内存峰值；包含低对比、旋转、多码、大截图、HEIC。识别率和目标正确性达标后，再根据耗时、内存、包体及兼容性决定主引擎。
